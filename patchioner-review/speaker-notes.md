# Patch-ioner · 페이지별 이해 해설

## 01. One Patch to Caption Them All

이 페이지는 **발표할 논문과 발표자를 소개하는 장**이야. 여기서 기술적인 원리까지 설명할 필요는 없어.

대신 “왜 갑자기 이 논문을 소개하는지”를 다음 장에서 설명하겠다고 연결하면 돼.

> “저희는 대체텍스트 품질 판정 대회를 준비하면서, 이미지에서 필요한 정보를 추출하는 방법을 조사하고 있습니다. 그중 선택한 이미지 영역을 설명할 수 있는 Patch-ioner 논문을 소개하겠습니다. 먼저 대회 주제와 이 논문을 선정한 배경부터 말씀드리겠습니다.”

## 02. Competition : 한국어 웹 대체텍스트 품질 판정

이 페이지는 **우리의 최종 목표가 무엇인지** 설명하는 장이야.

대회는 사진을 보고 새로운 설명문을 만드는 것에서 끝나는 게 아니야. **이미 붙어 있는 대체텍스트가 적절한지 판단**해야 해.

예를 들어 행사 사진의 대체텍스트가 그냥 “사진”이면 정보가 부족하겠지. 반대로 이미지가 링크 버튼이라면, 생김새보다 “어디로 이동하는 버튼인지”가 중요할 수도 있어.

> “대회의 목표는 이미지와 웹 문맥을 함께 활용해서 기존 대체텍스트의 품질을 판정하는 것입니다. 이미지에 어떤 정보가 있는지, 웹에서 어떤 역할을 하는지 확인한 뒤, 기존 설명의 누락이나 불일치 등을 구분해야 합니다.”

**여기서 강조할 것:** Description 추출은 최종 판정을 위한 **중간 단계**야.

근거: AIDA 대회 공식 문제 안내 · KoAltQ README / 라벨링 가이드 v0.2

## 03. Sample data : 장면과 세부 정보의 동시 확인

이 페이지는 **실제 데이터가 단순한 사물 사진만으로 구성되어 있지 않다는 것**을 보여주는 장이야.

왼쪽 행사 사진에서는 사람만 보는 게 아니라 건물의 이름, 사람들의 행동, 리본 같은 행사 도구를 함께 확인할 수 있어. 오른쪽 홍보물에는 큰 제목 외에도 점검 기간과 여러 안전수칙이 들어 있어.

즉, “행사 사진”, “안전 안내문” 같은 전체 요약만으로는 담긴 정보를 충분히 파악하기 어려운 사례를 보여주는 거야.

> “실제 샘플을 보면 한 이미지 안에 여러 종류의 정보가 함께 있습니다. 행사 사진에는 장소와 행동 정보가 있고, 홍보물에는 기간과 세부 수칙이 있습니다. 따라서 전체적인 장면과 작은 영역의 정보를 함께 확인할 필요가 있습니다.”

**주의:** 모든 세부 정보를 최종 alt에 다 넣어야 한다고 말하면 안 돼. 우선 판정할 근거를 확보한다는 의미야.

근거: KoAltQ sample · r00737652af / r0be9f0f533 · 제공 라벨: 모두 불충분형

## 04. Sample data : 작은 글자와 표의 관계까지

이 페이지는 앞 장보다 한 단계 더 들어가서, **글자를 읽는 것뿐 아니라 정보 간 관계도 알아야 한다**는 장이야.

표에서 날짜 하나, 장소 하나를 각각 읽었더라도 서로 다른 행의 정보를 연결하면 틀린 설명이 돼.

예를 들어 “12월 14일 교육 장소”를 확인하려면, 날짜와 장소가 **같은 행에 있는지**까지 알아야 해.

> “이 일정표는 제목만 읽어서는 실제 교육 내용을 알기 어렵습니다. 과정, 날짜, 장소, 인원을 읽고 서로 어떻게 연결되는지도 확인해야 합니다. 따라서 이미지 설명뿐 아니라 OCR과 표 구조 이해도 함께 검토하고 있습니다.”

**다음 장 연결:** 이렇게 얻은 정보들을 우리 시스템에서 어떻게 사용할지 보여주면 돼.

근거: KoAltQ sample · r28b16068d4 · 기존 alt 원문 / 제공 라벨: 불충분형

## 05. Our approach : 시각 근거를 모아 품질 판정

이 페이지는 **우리가 만들려는 전체 시스템 지도**야.

각 단계의 역할을 나눠서 설명하면 이해하기 쉬워.

```text
이미지 설명·OCR
    = 사진 안에 무엇이 있는지 정보 확보

기존 alt + 메타데이터
    = 현재 어떤 설명이 붙었고, 어떤 문맥에서 쓰였는지 확인

LLM Agent
    = 두 정보를 비교하고 품질 판단
```

> “먼저 이미지에서 전체 장면과 세부 정보를 추출합니다. 여기에 기존 대체텍스트와 페이지 제목, 인접 문맥 등의 정보를 함께 넣고, Agent가 설명의 적절성을 판단하도록 구성하려고 합니다. 주어진 정보만으로 판단하기 어려운 경우에는 웹 확인을 추가하는 방향도 고려하고 있습니다.”

**중요:** 지금은 **제안한 구조**야. 이미 정확성과 속도를 검증한 완성 시스템처럼 설명하면 안 돼.

근거: 팀 제안 구조 · 구현 및 성능 검증 전

## 06. Implementation plan : 단계별 도입 구성

이 페이지는 **앞 장의 각 역할을 어떤 도구로 구현할 계획인지** 설명하는 장이야.

- **Gemma 12B-QAT:** 정보를 비교하고 판단하는 모델
- **Python Agent:** 정보를 모으고 처리 순서와 도구 사용을 관리하는 프로그램
- **Vision pipeline:** 이미지 설명과 글자를 추출하는 부분
- **Playwright:** 필요한 웹페이지를 열고 확인하는 도구

특히 **Playwright 자체가 정답을 판단하는 AI는 아니라는 점**을 이해하면 돼.

> “판정 모델은 Gemma 12B-QAT를 후보로 두고, 처리 과정은 Python 기반 Agent로 구현할 계획입니다. 이미지 설명과 OCR 방법을 먼저 검토하고, 이후 필요한 경우 Playwright를 이용한 웹 확인 기능을 추가하려고 합니다.”

근거: 팀 구현 계획 · 1차 Agent / 2차 선택적 Browsing

## 09. Introduction : 기존 방식의 문제점

여기부터는 **우리 대회의 문제에서 논문 저자들이 해결하려는 문제로 넘어가는 장**이야.

문제는 두 가지야.

1. 전체 이미지 설명은 사용자가 원하는 작은 영역을 중심으로 설명하기 어려움.
2. 영역 설명을 직접 학습시키려면 영역과 정답 문장을 짝지은 데이터가 필요함.

> “기존 이미지 캡셔닝은 사진 전체를 요약하는 데 초점이 있습니다. 원하는 작은 영역을 설명하도록 별도로 학습하려면, 각 영역의 위치와 대응하는 정답 문장을 준비해야 합니다. 다양한 영역과 조합까지 고려하면 데이터 구축 부담이 커집니다.”

**다음 장 연결:** “그래서 저자들은 설명의 기본 단위를 바꾸었습니다.”

## 10. Introduction : Patch-centric captioning

이 페이지는 **논문의 핵심 아이디어를 처음 제시**하는 장이야.

사진 전체를 하나로 취급하는 대신, 사진을 구성하는 작은 구역인 **Patch**를 기본 단위로 삼는 거야.

- 패치 하나 선택 → 작은 부분 설명
- 패치 여러 개 선택 → 특정 영역 설명
- 모든 패치 선택 → 전체 이미지 설명

> “저자들은 설명의 기본 단위를 이미지 전체에서 패치로 바꾸었습니다. 필요한 패치의 특징을 모으면 작은 영역부터 전체 이미지까지 같은 처리 방식으로 설명할 수 있습니다.”

여기서는 평균이나 Memory 계산을 자세히 설명하지 말고, **선택하는 패치가 달라지면 설명 범위가 달라진다**는 아이디어만 전달하면 돼.

근거: Figure 1B · §3.2 From Patches to Regions

## 11. Our contributions

이 페이지는 **논문에서 새롭게 기여한 것을 세 가지로 정리**한 장이야.

- **Unified framework:** 여러 형태의 영역을 같은 구조로 설명
- **Zero-shot regional captioning:** 영역–문장 정답 쌍으로 직접 학습하지 않고 영역 설명
- **Component analysis and evaluation:** 어떤 구성요소가 중요한지 비교하고 실제 성능 평가

> “첫째, 다양한 영역의 캡셔닝을 패치 중심의 하나의 구조로 통합했습니다. 둘째, 기존 모델과 텍스트로 학습한 생성기를 연결해 영역 설명으로 확장했습니다. 셋째, 어떤 특징 추출 방식이 적합한지 분석하고 여러 과제에서 성능을 평가했습니다.”

**Zero-shot 주의:** 모든 모델이 아무런 사전학습도 하지 않았다는 뜻은 아니야. 기존에 학습된 모델을 활용하되, 여기서 영역–문장 쌍으로 직접 가르치지 않는다는 의미야.

## 12. Related work : CLIP과 DINOv2의 역할

이 페이지는 **뒤에서 등장할 모델들이 각각 무엇을 잘하는지** 소개하는 장이야.

| 모델 | 쉽게 이해할 역할 |
|---|---|
| CLIP | 이미지와 문장의 의미를 연결 |
| DINOv2 | 이미지의 위치별 시각 특징 추출 |
| Talk2DINO | CLIP의 문장 특징을 DINOv2 특징과 비교할 수 있도록 연결 |

> “CLIP은 이미지와 문장을 연결하는 데 강점이 있지만, 전체 이미지 중심의 학습이 작은 패치의 의미까지 충분히 보장하지는 않습니다. DINOv2는 위치별 시각 특징에 강점이 있고, Talk2DINO는 여기에 텍스트와의 연결을 제공합니다.”

**핵심:** DINOv2가 직접 문장을 생성하는 게 아니야. **이미지 특징 추출과 문장 생성은 서로 다른 역할**이야.

근거: §2 Language-aligned Dense Representations · §4.2

## 13. Related work : Zero-shot captioning의 확장

이 페이지는 **텍스트만으로 문장 생성기를 학습하는 아이디어 자체는 기존에도 있었다**는 배경 설명이야.

기존 방법은 대체로 이렇게 생각했어.

> “문장의 특징을 보고 원래 문장을 복원하도록 생성기를 학습하면, 나중에는 이미지 특징으로도 문장을 만들 수 있지 않을까?”

다만 이미지와 문장의 특징 차이를 보완해야 했고, 주로 전체 이미지 설명에 사용됐어.

> “기존 Zero-shot captioning 연구들은 텍스트 특징에서 문장을 복원하도록 생성기를 학습하고, 이를 이미지 특징에 적용하는 방법을 사용했습니다. 이 논문은 그러한 생성 방식을 지역 정보가 풍부한 패치 특징과 연결해 원하는 영역의 설명으로 확장합니다.”

**이후 설명 범위:** 여러 변형 중 **Talk2DINO + Memory 조합**을 대표로 설명한다고 알려주면 좋아.

근거: §2 Zero-shot Image Captioning · §3

## 14. Methods : 모델 구성과 학습 범위

이 페이지는 **무엇을 가져다 쓰고, 무엇을 새로 학습하는지** 구분하는 장이야.

여기서 가장 중요한 구분은:

> **모델 = 계산하는 장치 / 벡터 = 그 장치에 입력을 넣어서 나온 계산 결과**

DINOv2, CLIP 텍스트 인코더, Talk2DINO 연결은 기존 학습 결과를 고정해서 사용하고, 대표 구성에서는 문장 생성기를 텍스트로 학습해.

> “이 구성에서는 특징 추출 모델과 연결 모듈을 고정하고 문장 생성기를 학습합니다. 학습되는 것은 모델 내부의 파라미터입니다. 반면 이미지나 문장에서 나오는 특징 벡터는 입력마다 계산되는 결과입니다.”

**이 장에서 잡아야 할 오해:** 벡터가 새로 계산됐다고 모델이 새로 학습된 건 아니야.

근거: §3 Assumptions · §3.1 · §4.2 · 대표 조합: Talk2DINO + Memory

## 15. Methods : Image–Text feature alignment

이 페이지는 네가 처음에 궁금해했던 **“이미지에서 나온 숫자와 문장에서 나온 숫자를 어떻게 비교하냐?”**에 답하는 장이야.

두 경로를 따로 짚어줘.

```text
이미지 → DINOv2 → 이미지 유래 특징 V

문장 → CLIP text encoder → Talk2DINO → 텍스트 유래 특징 T
```

Talk2DINO를 통과한 T는 **DINOv2 특징 공간에서 비교할 수 있는 표현**이 돼.

> “이미지와 문장은 서로 다른 경로로 특징을 얻습니다. Talk2DINO는 문장 특징을 DINOv2 특징 공간과 연결해, 이미지 패치와 문장의 의미를 비교할 수 있도록 합니다.”

**주의:** 숫자 개수가 같다는 것만으로 비교가 의미 있어지는 건 아니야. **의미가 대응하도록 사전에 학습된 연결**이 있어야 해. 또 같은 공간이라고 두 종류의 특징이 완전히 같아지는 것도 아니야.

근거: §2 Talk2DINO · §3 · §4.2 · 개념도

## 16. Methods : Text-only decoder training

이 페이지는 **문장 생성기를 실제로 어떻게 학습시키는지** 보여주는 장이야.

`A dog runs.`라는 문장을 예로 들면:

1. 문장을 CLIP과 Talk2DINO에 넣어 T를 계산.
2. 생성기가 T를 보고 원래 문장을 복원하도록 학습.
3. 예측한 다음 토큰과 원래 문장의 정답 토큰을 비교.
4. 차이가 줄어들도록 생성기의 파라미터 수정.

> “원래 문장에서 특징 벡터를 만든 뒤, 그 특징을 조건으로 원래 문장을 복원하도록 생성기를 학습합니다. 이때 원래 문장 자체가 정답 역할을 하므로, 생성기 학습에 이미지와 영역별 정답 문장 쌍은 사용하지 않습니다.”

**정확히 짚을 부분:** 여기서 줄이는 것은 **이미지 벡터와 문장 벡터의 거리**가 아니라, **생성기가 예측한 토큰과 정답 토큰 사이의 오차**야.

근거: §3.1 Zero-shot decoding · §4.2 · 개념도

## 17. Methods : Text memory 준비

이 페이지는 **나중에 이미지 특징을 보완하는 데 사용할 참고 자료를 만드는 과정**이야.

여러 문장을 같은 변환 경로에 넣어서 T₁, T₂, T₃…를 얻고 저장해.

```text
여러 문장 → CLIP + Talk2DINO → 여러 T 벡터 → 저장소
```

> “Memory는 여러 문장에서 미리 계산한 특징 벡터를 저장한 것입니다. 새로운 모델을 학습하는 과정이 아니라, 이미 학습된 모델로 특징을 계산하고 저장하는 과정입니다.”

**16페이지와 차이:**

- 16페이지: 생성기의 계산 규칙을 **학습**
- 17페이지: 나중에 참고할 벡터들을 **계산·저장**

Memory 자체가 문장을 만드는 모델은 아니야.

근거: §4.2 Memory-based latent projection

## 18. Methods : 선택 영역의 Patch aggregation

이 페이지는 **이미지의 여러 패치 특징을 영역 하나의 특징으로 합치는 과정**이야.

강아지 영역에 패치가 여러 개 걸쳐 있으면, 그 패치들의 특징을 평균 내서 대표 벡터 V를 만들어.

> “먼저 이미지 전체에서 패치 특징을 추출한 뒤, 지정한 영역에 해당하는 패치만 선택합니다. 기본 집계 방식은 선택한 특징들의 평균이며, 여기에 별도로 학습할 파라미터는 없습니다.”

**여기서 강조할 것:** 평균을 내도 V는 여전히 **이미지에서 얻은 특징**이야. 평균만으로 문장 특징으로 바뀌지는 않아.

일부 전체 이미지 실험에서는 가중 평균을 사용하지만, 이 장에서는 기본 평균 원리를 설명하면 돼.

근거: §3.1 Parameter-free aggregation · §3.2

## 19. Methods : Modality gap과 보완 방법

이 페이지는 **왜 이미지 특징 V를 생성기에 바로 넣는 것만으로 충분하지 않은지** 설명해.

생성기는 학습할 때 **문장에서 얻은 T**를 봤어. 그런데 실제 사용에서는 **이미지에서 얻은 V**가 들어오잖아. 비교 가능한 같은 공간에 있어도 두 입력의 분포가 다를 수 있어.

비유하면, 같은 단위로 표현된 자료라도 실제로 자주 나타나는 값의 범위와 조합이 다른 거야.

> “문장 특징과 이미지 특징은 같은 공간에서 비교할 수 있지만, 분포까지 같지는 않습니다. 따라서 텍스트 특징으로 학습한 생성기에 이미지 특징을 입력하면 차이가 발생할 수 있고, 이를 줄이는 보완 과정이 필요합니다.”

이 장의 Memory, Noise, Diffusion은 **그 차이를 다루는 서로 다른 선택지**야. 전부 순서대로 적용한다는 뜻은 아니야.

근거: §3.1 · §4.2 · 이후 도식은 Memory 조합

## 20. Methods : Memory-based projection

이 페이지는 **Memory를 실제로 어떻게 사용하는지** 설명하는 핵심 장이야.

순서대로 설명하면 돼.

1. 이미지 영역의 특징 V와 저장된 T들을 비교.
2. T마다 유사도 점수 하나씩 계산.
3. Softmax로 점수를 합이 1인 비중으로 변환.
4. 그 비중대로 T들을 섞어 Z 생성.

예를 들어 설명용으로 비중이 0.7, 0.2, 0.1이라면:

```text
Z = 0.7 × T₁ + 0.2 × T₂ + 0.1 × T₃
```

> “현재 이미지 영역과 비슷한 텍스트 특징에 더 큰 비중을 주고, 그 특징들을 가중합합니다. 이렇게 만든 Z를 생성기에 전달해, 학습할 때 사용한 텍스트 특징과의 차이를 보완합니다.”

**꼭 구분해 줘:**

- **내적 결과:** 유사도 **점수**
- **가중합 결과:** 생성기에 넣을 **벡터 Z**
- **가중치:** 사진마다 계산되는 비중으로, 새로 학습하는 모델 파라미터가 아님

근거: §4.2 · V, T, Z는 설명용 기호

## 21. Methods : 이미지에서 Caption까지

이 페이지는 앞에서 나눠 설명한 과정을 **실제 사용 순서로 한 번에 연결**하는 장이야.

> “실제 이미지가 들어오면 DINOv2가 패치 특징을 추출합니다. 선택한 영역의 특징을 평균 내어 V를 만들고, Memory와의 유사도를 이용해 Z를 구성합니다. 마지막으로 이미 학습한 생성기에 Z를 넣어 설명문을 얻습니다.”

여기서는 앞 장의 세부 수식을 다시 길게 설명하지 말고, 화살표를 따라가면서 **사진에서 문장까지 이어지는 흐름**을 확인해 주면 돼.

**중요:** 이 과정에서 모델을 다시 학습하지 않아. **학습된 모델로 계산하는 단계가 Inference**야.

근거: §3 Framework · §4.2 · Talk2DINO + Memory

## 22. Methods : Caption generation

이 페이지는 **벡터를 넣었는데 어떻게 실제 문장이 나오냐?**를 설명하는 장이야.

생성기는 Z를 문장 생성용 힌트로 바꾸고, 이미 생성한 토큰과 함께 사용해서 다음 토큰을 계속 예측해.

```text
입력 힌트
   ↓
A → dog → is → running → … → 종료
```

토큰은 반드시 단어 하나와 같지는 않고, 단어의 일부일 수도 있어.

> “생성기는 입력 특징을 힌트로 사용해서 다음 토큰을 순차적으로 예측합니다. 앞에서 생성한 내용을 다시 조건으로 사용하고, 종료 토큰이 나오면 최종 문장이 완성됩니다.”

**출력은 최종적으로 문장**이야. 내부의 토큰 확률 벡터를 처음 입력한 특징 벡터와 혼동하지 않으면 돼.

근거: §3.1 Prefix language modeling · §4.2

## 23. Methods : Training과 Inference의 입력

이 페이지는 **학습할 때와 사용할 때 무엇이 달라지는지** 정리하는 장이야.

| 단계 | 생성기 입력 | 목적 |
|---|---|---|
| Training | 한 문장에서 얻은 T | 원래 문장 복원 능력 학습 |
| Inference | 이미지에 맞춰 T들을 섞은 Z | 새 이미지 영역의 설명 생성 |

> “학습할 때는 한 문장에서 얻은 T를 입력하고 원래 문장을 복원합니다. 실제 사용할 때는 이미지 특징과의 유사도에 따라 Memory의 T들을 가중합한 Z를 입력합니다.”

또한 **두 번의 합치기**를 구분해 주면 좋아.

- 패치 평균: 이미지 패치들을 합쳐 **설명할 영역 V**를 표현
- Memory 가중합: 텍스트 특징들을 합쳐 **생성기 입력 Z**를 구성

근거: §3.1 · §4.2 · Talk2DINO + Memory

모든 행을 똑같이 길게 읽기보다 세 묶음으로 말하면 돼.

## 28. Experiments : Metrics와 비교 조건

## 30. Results : Local features와 Captioning 성능

이 페이지는 **앞의 큰 표에서 핵심 비교만 뽑아 해석**하는 장이야.

Trace CIDEr는 CLIP 10.9, DINO.txt 23.2, Talk2DINO 27.9야. 다른 지역 과제에서도 같은 방향의 차이를 볼 수 있어.

> “지역 과제의 CIDEr만 보면 Talk2DINO가 CLIP보다 높은 점수를 보입니다. 이는 패치를 선택하고 평균 내는 연산만으로는 충분하지 않고, 각 패치가 지역의 의미를 잘 담고 있어야 한다는 점을 뒷받침합니다.”

**발표에서 가져갈 해석:**

> **“무엇을 합칠지뿐 아니라, 합치기 전 특징의 품질이 중요하다.”**

다만 Backbone의 모든 사전학습 조건을 동일하게 통제한 실험은 아니므로, 특정 구조 하나만이 차이의 유일한 원인이라고 단정하지는 않아.

## 32. Results : Regional captioning의 성능 개선

이 페이지는 **논문의 강점이 가장 잘 나타난 지역 설명 결과**를 설명하는 장이야.

- Trace CIDEr: **24.3 → 29.4**
- Dense mAP: **17.75 → 21.31**

> “지역 설명 과제에서는 제안 방법이 비교 모델보다 높은 점수를 보였습니다. 마우스로 지정한 영역, 개별 박스, 여러 영역의 집합을 설명하는 상황에서 패치 중심 접근의 강점이 나타났습니다.”

## 33. Results : Whole-image captioning

이 페이지는 **전체 이미지를 설명할 때도 최고인가?**를 확인하는 장이야.

여기서는 Patch-ioner의 T2D + Diffusion이 92.8이고, MERCap이 96.0, EntroCap이 94.3이야.

> “전체 이미지 설명에서는 경쟁력 있는 성능을 유지했지만, 비교한 최고 방법을 넘어서지는 못했습니다. 따라서 이 논문의 강점은 모든 캡셔닝 성능의 일괄적인 향상보다, 원하는 영역을 설명하는 유연성과 지역 과제 성능에 있습니다.”

또 앞의 Backbone 표와 숫자가 다를 수 있는데, 이 전체 이미지 비교에는 **attention 기반 가중치가 적용된 조건**이 포함돼 있어. 서로 다른 표의 수치를 같은 설정으로 단정하면 안 돼.

## 34. Results : 선택 영역과 생성 Caption

이 페이지는 **점수 차이가 실제 문장에서는 어떻게 보이는지** 보여주는 장이야.

대표적으로 기차역의 시계를 선택한 사례를 설명하면 좋아.

- 기존 방법: 기차나 전체 역 장면을 설명
- 제안 방법: 지정한 시계를 중심으로 설명

> “정성적 예시에서도 지정한 영역을 반영하는 차이가 보입니다. 기차역 사진에서 시계 영역을 선택했을 때, 제안 방법은 시계를 중심으로 설명하는 모습을 보입니다.”

그리고 균형 있게 덧붙여:

> “다만 다른 예시에서는 영역 밖의 내용이나 잘못된 행동·위치 표현도 나타납니다. 선택 영역을 더 잘 반영하는 것과 설명이 항상 정확한 것은 구분해야 합니다.”

## 35. Discussion : Patch-centric 접근의 의의

이 페이지는 **그래서 이 연구가 어떤 의미가 있는지** 해석하는 장이야.

핵심은 영역 종류마다 완전히 다른 모델을 만드는 대신, **선택할 패치 집합을 바꿔 같은 구조를 재사용한다**는 점이야.

그리고 이미지 특징은 한 번 추출한 뒤 여러 영역에서 재사용할 수 있어.

> “이 방법은 설명할 영역의 형태가 달라도 패치 선택과 집계라는 공통 구조로 처리할 수 있습니다. 또 이미지 특징을 한 번 추출한 뒤 여러 영역의 설명에 재사용할 수 있어, 사용자가 설명 위치를 바꾸는 응용에 활용할 가능성이 있습니다.”

**주의:** 특징을 재사용한다고 모든 계산이 없어지는 건 아니야. 영역 집계와 문장 생성은 다시 해야 하고, 실제 응답 속도도 별도로 확인해야 해.

근거: §4.2–4.3 · §5 Conclusions

## 36. Limitations

이 페이지는 **이 방법을 사용할 때 어디까지 믿고 어디를 추가 검증해야 하는지** 설명하는 장이야.

네 가지로 묶으면 돼.

1. 영역 정답자료로 직접 학습한 전문 모델과의 성능 격차
2. 선택한 패치 밖의 맥락이 설명에 섞일 가능성
3. 사진에 없는 내용을 생성하는 Hallucination
4. 정답 박스를 제공한 평가이므로 자동 영역 탐지 성능은 미검증

> “이 방법은 영역별 직접 학습 없이 설명할 수 있다는 장점이 있지만, 완전 지도학습 모델과의 성능 차이와 환각 문제가 남아 있습니다. 또한 선택 영역의 주변 맥락을 어디까지 반영할지 제어하기 어렵고, 자동 영역 탐지까지 평가한 것은 아닙니다.”

우리 대회와 연결하면 **‘중요 영역을 어떻게 선택하고, 생성한 설명을 어떻게 검증할지’가 추가 과제**라는 뜻이야.

근거: §5 Limitations and Future Work · §4.1 Dense evaluation

## 37. Conclusion

이 페이지는 **논문에서 확인한 것과 우리 프로젝트에 가져갈 판단을 정리**하는 마지막 장이야.

이렇게 마무리하면 전체 발표 흐름이 처음의 대회 주제로 돌아와.

> “이 논문은 패치를 기본 단위로 사용해 다양한 영역의 캡셔닝을 하나의 구조로 통합했습니다. 이를 위해서는 지역 의미를 잘 담는 특징과 이미지·텍스트 입력 차이에 대한 보완이 중요했고, 실험에서도 지역 설명 과제의 성능 개선을 확인했습니다.”

이어서 우리 계획으로 연결해:

> “따라서 저희는 이를 이미지의 세부 영역 설명을 확보하는 후보로 검토할 수 있습니다. 다만 OCR, 중요한 영역의 선택, 설명의 사실성은 별도로 확인해야 하므로, 실제 대회 샘플에서 정보 누락과 오류를 비교하는 과정이 필요합니다.”

**“이 논문이 대회 문제를 전부 해결한다”가 아니라, “전체 시스템 중 이미지 근거를 확보하는 한 부분으로 검토한다”**는 위치를 분명히 잡으면 돼.
